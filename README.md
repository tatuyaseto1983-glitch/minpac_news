# 民泊コンパス

民泊・簡易宿所・旅館業法のニュースを、行政の一次情報から自動で集めて公開する静的サイトです。
**サーバー不要・外部ライブラリなし・追加費用なし**（GitHub Actions と GitHub Pages の無料枠で動きます）。

## 動かす

```bash
npm run fetch    # 行政サイトから収集して data/*.json を更新
npm run build    # dist/ に静的サイトを生成
npm run serve    # http://localhost:8080 で確認
npm run preview  # 全ページを1枚にまとめた dist/preview.html を作る（共有用）

# 任意：行政ページの中身を読んで「つまりどうなる」の要約を付ける（APIキーが要ります）
OPENAI_API_KEY=sk-...    npm run summarize -- --limit 20
ANTHROPIC_API_KEY=sk-... npm run summarize -- --limit 20
```

まとめて実行するなら `npm run update`。Node.js 20 以上が必要です。

npm のパッケージは1つも使いませんが、**PDFを読むところだけ `pdftotext` を借ります**（観光庁の届出件数の表が
PDFでしか公開されていないため）。手元で試すときは `sudo apt-get install poppler-utils`、
macOS なら `brew install poppler`。入っていなくても、その1件がとばされるだけで他はふつうに動きます。

## 自動更新

`.github/workflows/update.yml` が毎日 05:20（日本時間）に動き、

1. 行政サイトから収集
2. `data/articles.json` と `data/stats.json` の差分をコミット
3. サイトを生成して GitHub Pages に公開

という流れで更新します。

### 公開のしかた（初回だけ）

1. GitHub のリポジトリ → **Settings → Pages** を開く
2. **Build and deployment** の **Source** を「**GitHub Actions**」に変更
3. **Actions** タブ →「サイト更新（毎日）」→ **Run workflow** を1回実行

> **この1と2は人の手でやる必要があります。** ワークフローの権限では Pages を新規作成できず、
> `Create Pages site failed. Error: Resource not accessible by integration` で失敗します。
> 一度有効にすれば、以降はワークフローだけで更新・公開されます。

数分後、次のURLで誰でも見られるようになります。

```
https://tatuyaseto1983-glitch.github.io/minpac_news/
```

以降は毎朝5時20分（日本時間）に自動で更新されます。

記事の本文は保存していません。保存しているのは見出し・公開日・発表元・リンクだけです。
同じ出来事を複数の媒体が報じている場合は、見出しの文字の重なり具合で1つの話題にまとめ、
代表の1件だけを出して「ほか◯媒体」と添えます。

記事は1件を左右に分けて出します。左が見出しとタグ、右が「どんな影響がありそうか」です。
写真は使いません（用意する手間も、外部画像を借りる著作権の問題もないため）。

右側の文は、AI要約 →『一言メモ』→ 見出しの動きから組み立てた文 → 分類から組み立てた文、の順で
あるものを使います。後ろの2つは記事の中身ではなくこちらの分類から作った文なので、
ラベルを「どう効きそうか」「関係しそうな方」と分けて、記事の要約と混ざらないようにしています。

## 調査レポートを載せる

`content/reports/` にHTMLファイルを置くだけで、サイトの「レポート」に載ります。
中身は書き換えません。作ったときの見た目のまま公開されます。

- 表題・要約・日付・対象エリアは、HTMLの中から自動で読み取ります
- 同じ名前で `.json` を置けば、表題や要約を自分で決められます
- 同じ名前で `.pdf` を置くと「PDF版」のリンクが付きます
- **公開したくないものは `_private/` へ**（公開もGitへの記録もされません）

対象エリアが読み取れると、その都道府県のページからもリンクされます。
レポートが1本も無いときは、ヘッダーの「レポート」も一覧ページも出ません。
詳しくは `content/reports/README.md` を見てください。

## 宿泊の統計について

延べ宿泊者数・客室稼働率は、**観光庁の報道発表ページの本文から読み取っています**（`parseLodgingStats`）。毎月更新され、全国の値と前年同月比が本文にそのまま書かれています。

e-Stat の API も使える状態にしてありますが、**宿泊旅行統計調査のデータベースは2016年分で更新が止まっています**（統計コード 00601020、32表すべて。最終更新2019年3月）。最新分はファイル提供のみでAPIから取れないため、いまは使っていません。都道府県別の最新値も、このため未取得です。

e-Stat の仕組み自体は動くので、ほかの統計を足したくなったときにそのまま使えます。

## 都道府県ごとの届出件数について

観光庁の「都道府県別届出状況一覧」はPDFでしか公開されていません。そこで `pdftotext -layout` で
表を文字に起こしてから読み取っています（`parseFilingsPdf`）。

表は「都道府県」「保健所設置市」「特別区」の3つの列が横に並んでいるので、行の名前の末尾（県／市／区）で
どの列かを見分け、市は都道府県に、特別区は東京都に足して合算します。たとえば東京都の件数は
「都の分＋八王子市など＋23区」の合計です。

読み取った結果は、**PDF自身の集計欄と突き合わせています**。1件でも数が合わなければ取り込みません。
表の作りが変わったときに、間違った数字が静かに公開されるのを防ぐためです。

PDFのURLは更新のたびに変わるので、施行状況ページの見出しの文言から毎回探し直しています。

## 都道府県ごとの宿泊需要について

延べ宿泊者数・外国人比率・客室稼働率の**都道府県別**の数字は、観光庁の報道発表の添付PDFにしか
載っていません（ページ本文は全国の値だけ）。こちらも `pdftotext` で3つの表を読み取っています
（`parseLodgingPdf`）。読み取った47都道府県を足して、表の「全国」の行と合うかを確かめています。

この3つの表は**第2次速報**なので、本文の全国値より1か月前の時点です。サイトでも時点を分けて書いています。

データページの「泊まる人は多いのに、民泊が少ない地域」は、この延べ宿泊者数を届出住宅数で割ったものです。
需要の受け皿はホテルや旅館もあるため、この数字だけでは判断できません。客室稼働率と並べて見るための
入口として置いています。

## e-Stat をつなぐ（他の統計を足すとき）

延べ宿泊者数・客室稼働率・外国人比率は、e-Stat の API から取り込みます。無料ですが、**アプリケーションIDの取得だけ人の手が必要**です。

1. https://www.e-stat.go.jp/api/ で利用登録（メールアドレスのみ、無料）
2. ログイン後、マイページで **アプリケーションIDを発行**（URL欄には実際に公開しているサイトのURLを入れます。`localhost` やプライベートIPは登録できません）
3. GitHub のリポジトリ → **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `ESTAT_APP_ID`
   - Secret: 発行されたID

登録すると、次の自動更新のときに統計表の候補一覧が Actions のログに出ます。そこから使う表を選んで `data/estat.json` の `statsDataId` に入れると、データページに数字が並びます。

手元で試す場合：

```bash
ESTAT_APP_ID=xxxx npm run estat -- --list            # 表を探す
ESTAT_APP_ID=xxxx npm run estat -- --meta 0003314402 # 表の中身を見る
ESTAT_APP_ID=xxxx npm run estat                       # 設定にしたがって取り込む
```

IDが未設定でも何もせず終了するので、自動更新は止まりません。

## 注意

制度の適用可否など最終的な判断は、必ず物件所在地の管轄窓口（保健所・消防署・建築指導課）へご確認ください。
自動で集めて自動で分類しているため、カテゴリやエリアの判定には誤りが含まれることがあります。
