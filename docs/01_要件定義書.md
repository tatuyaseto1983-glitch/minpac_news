# 民泊・宿泊ニュースサイト 要件定義書

- 案件名：民泊／簡易宿所／旅館業法に特化したニュースメディアの立ち上げ
- 仮称：**MINPAKU COMPASS（民泊コンパス）**
- 版数：v1.0（初版）
- 作成：SUMUS コンサル事業部

---

## 1. 結論：何を作るのか

**「民泊をこれから始める人・すでに運営している人が、法律とお金の最新情報をここだけ見ておけば把握できる」サイトを作ります。**

具体的には次の3つを1画面にまとめます。

1. **国の発表**（観光庁・厚生労働省などの一次情報を自動で取り込む）
2. **地域のルール**（都道府県・市区町村ごとの条例や上乗せ規制をまとめる）
3. **業界のニュース**（信頼できる報道の見出しと要約、出典リンク）

例えるなら「天気予報アプリの民泊版」です。気象庁の生データ（＝行政の発表）をそのまま見ても分かりにくいので、「今日は傘が要ります」（＝あなたの地域では今こうなります）まで翻訳して届けます。

---

## 2. なぜ作るのか（背景）

- 民泊の情報は**バラバラの場所に散らばっています**。国の発表は観光庁、営業許可は保健所、消防は消防署、建物は建築指導課。それぞれサイトが違います。
- しかも**地域ごとにルールが違います**。同じ「民泊」でも、住宅宿泊事業法（年180日）、旅館業法の簡易宿所（日数制限なし）、特区民泊（対象地域限定）で、必要な手続きも投資額も変わります。
- 一方で、既存の民泊メディアの多くは**運営代行会社の集客記事**が中心で、制度そのものを継続的に追いかけている中立的な媒体が少ない状況です。

→ ここに、**「制度の変化を定点観測する中立メディア」**という空きがあります。

### SUMUS にとっての位置づけ

このサイトは単体の広告収入を狙うものではなく、**新規事業（民泊参入支援）のリード獲得と信頼構築の入口**として設計します。
「調べているうちにSUMUSを知り、無料診断に申し込む」という流れを作ります。

---

## 3. 誰に向けるのか

| 対象 | 状況 | 知りたいこと |
| --- | --- | --- |
| **A. これから始める人**（最優先） | 空き家・遊休不動産を持つオーナー、工務店・不動産会社の新規事業担当 | 自分の物件で開業できるか。何日で、いくらかかるか |
| **B. すでに運営している人** | 1〜数棟のホスト、運営代行会社 | 制度変更、条例改正、行政指導の動き |
| **C. 支援する立場の人** | 工務店・リフォーム会社・士業・金融機関 | 顧客に説明できる正確な情報、市場データ |

最初は **A に全振り**します。理由は、SUMUSの支援メニューと直結し、成果（問い合わせ）が測りやすいためです。

---

## 4. 提供する価値（他サイトとの違い）

1. **一次情報に必ずリンクを張る** — 「観光庁が○月○日に出した資料」まで辿れる状態にします。
2. **地域で絞り込める** — 「自分の市はどうなのか」に3クリック以内で到達します。
3. **数字を継続的に出す** — 届出件数、宿泊者数、稼働状況を定期更新のグラフで見せます。
4. **専門用語を使わない** — 記事の冒頭は必ず「つまりどうなるか」を3行で書きます。

## 5. 情報の集め方

### 5-1. 一次情報（行政データ）— 自動取得

| 情報源 | 内容 | 取得方法 | 更新頻度 |
| --- | --- | --- | --- |
| 国土交通省 新着情報・プレスリリース RSS<br>（`/index.rdf`, `/pressrelease.rdf`） | 観光庁を含む省全体の発表 | RSS取得 → キーワード絞り込み | 毎日 |
| 観光庁 報道発表ページ | 宿泊統計、制度改正、通知 | ページ巡回（スクレイピング） | 毎日 |
| 民泊制度ポータルサイト「minpaku」 | 住宅宿泊事業法の施行状況、届出件数、Q&A | ページ巡回 | 週1 |
| e-Stat API（政府統計） | 宿泊旅行統計調査 ほか | API（要：無料の利用登録とappID） | 月1 |
| 厚生労働省 | 旅館業法関連の通知・改正 | ページ巡回 | 週1 |
| 各都道府県・政令市のオープンデータ | 届出施設一覧、条例、要綱 | CSV／ページ巡回（自治体ごとに形式が異なる） | 月1 |

> **留意点：** 自治体のデータ公開形式は統一されていません。全国一括での自動化は難しいため、**まず主要20自治体を手作業＋半自動で整備し、順次広げる**方針とします。

### 5-2. 二次情報（報道）— 自動収集＋人の確認

- 対象：全国紙・地方紙・観光業界紙・信頼できる専門メディアの **RSSまたは公開ページ**
- 扱い方：**見出し・公開日・出典元名・リンクのみを掲載し、本文は転載しません。** 記事内容は自社で書き直した要約（2〜3行）を添えます。
- 判断：AIが下書きを作り、**公開前に必ず人が1回確認**します（後述のリスク管理）。

### 5-3. 独自情報

- 自治体の担当課への電話確認メモ（「事前相談は必要か」など実務レベルの情報）
- SUMUSの支援現場から出てくる実例（匿名化した上で）

## 6. 情報の分類設計

### カテゴリ（記事は必ず1つに属する）

1. **法制度・法改正** — 住宅宿泊事業法、旅館業法、特区民泊
2. **自治体ルール** — 条例、上乗せ規制、運用の変更
3. **統計・マーケット** — 宿泊者数、稼働率、届出件数、インバウンド動向
4. **開業実務** — 手続き、消防、建築、保険、税務
5. **補助金・支援制度** — 国／自治体の助成
6. **業界動向** — 事業者のニュース、サービス、M&A

### タグ（複数付与可）

- エリア：都道府県 → 市区町村
- 事業形態：住宅宿泊事業／簡易宿所／特区民泊／旅館・ホテル
- 対象者：これから始める人／運営中／支援者

## 7. 画面と機能

### 第1段階（MVP：3か月で公開）

| No | 画面 | 主な機能 |
| --- | --- | --- |
| 1 | トップページ | 重要ニュース、新着一覧、注目の数字、エリア入口 |
| 2 | 記事一覧 | カテゴリ／エリア／事業形態で絞り込み、並び替え |
| 3 | 記事詳細 | 3行要約、本文、出典リンク、関連記事、CTA |
| 4 | エリア別ページ（47都道府県） | その地域のルール概要、届出件数、関連記事 |
| 5 | データページ | 届出件数の推移、宿泊者数のグラフ（更新日を明記） |
| 6 | 用語集 | 専門用語をやさしく説明（記事から自動リンク） |
| 7 | 検索結果 | キーワード検索 |
| 8 | メルマガ登録／問い合わせ | リード獲得（SUMUSの無料相談へ） |

### 第2段階（公開後3〜6か月）

- **開業できるか簡易診断**（住所・建物種別・希望日数を入れると、想定される制度と必要手続きを提示）
- **自治体ルールのデータベース**（条例の要点を項目ごとに比較できる表）
- 週次メールマガジンの自動生成
- 会員登録（資料ダウンロードと引き換えに連絡先を取得）

## 8. データの持ち方（記事の項目）

```
記事（Article）
  ├ タイトル
  ├ 3行要約
  ├ 本文
  ├ カテゴリ（1つ）
  ├ タグ（エリア／事業形態／対象者）
  ├ 出典（複数可：媒体名・URL・公開日・一次情報かどうか）
  ├ 公開日／更新日
  ├ 重要度（速報／通常／参考）
  ├ ステータス（下書き／確認待ち／公開）
  └ 執筆者・確認者

自治体（Municipality）
  ├ 都道府県／市区町村
  ├ 制度別の可否と条件（住宅宿泊／簡易宿所／特区）
  ├ 上乗せ規制の要点（区域制限・日数制限・事前手続き）
  ├ 担当課と連絡先
  ├ 根拠となる条例・要綱のURL
  └ 最終確認日 ← ★必ず表示する

統計（Statistic）
  ├ 指標名／地域／期間／数値／単位
  ├ 出典（e-Stat 等）
  └ 取得日
```

> **「最終確認日」を全ページに出す**ことを必須要件とします。制度情報は古いと事故につながるためです。食品の賞味期限表示と同じ考え方です。

## 9. 技術構成（案）

推奨は **A案**です。運用の手離れがよく、初期費用を抑えられます。

| | A案：ヘッドレスCMS構成（推奨） | B案：WordPress構成 |
| --- | --- | --- |
| 表示側 | Next.js（Vercel） | WordPress テーマ |
| 記事管理 | microCMS | WordPress管理画面 |
| 収集の仕組み | GitHub Actions で定期実行（RSS取得→整形→AI要約→下書き登録） | 同左（外部サーバー必要） |
| データ保管 | Supabase（自治体・統計データ） | MySQL |
| 検索 | Algolia もしくは内製 | プラグイン |
| 費用感（月） | 約1〜3万円 | 約1〜2万円 |
| 向き不向き | 表示が速い。データページを作りやすい | 記事だけなら手軽。データ活用は弱い |

いずれの案でも、**収集の自動化と、公開前の人による確認**はセットで組み込みます。

## 13. リスクと留意点

| リスク | 内容 | 対策 |
| --- | --- | --- |
| **著作権** | 他社記事の本文を転載すると権利侵害になります | 見出し・出典・リンクのみ掲載。要約は自社の言葉で書き直す。RSS配信の範囲を超えない |
| **行政データの利用条件** | 各サイトの利用規約に従う必要があります | 出典を必ず明記。政府標準利用規約に沿った表示を行う。加工した場合はその旨を記載 |
| **情報の誤り** | 制度を誤って伝えると読者に実害が出ます | ①AI要約は必ず人が確認 ②「最終確認日」を全ページ表示 ③「最終判断は必ず管轄の窓口へご確認ください」の注記を常設 |
| **スクレイピングの負荷** | 行政サイトへ過度なアクセスをすると迷惑になります | 取得間隔をあける（1日1回、深夜帯）。RSSがあるものはRSSを優先 |
| **法律相談との線引き** | 個別案件の判断は行政書士等の業務範囲です | サイトは一般情報の提供にとどめ、個別相談は提携先の士業へ案内する |
| **更新が止まる** | メディアが放置されると逆効果です | 自動収集で最低限の新着が途切れない設計にする。運用工数を先に確保する |
