# 情報ソース仕様（収集の設計メモ）

要件定義書の第5章を、開発向けに具体化したものです。

## 1. 基本方針

- **一次情報（行政）が主、報道が従。** 報道は「気づくきっかけ」として使い、記事の根拠は必ず行政の元資料に置きます。
- **取得は1日1回、深夜帯。** 行政サイトに負荷をかけないため、同一ホストへの連続アクセスは1秒以上あけます。
- **AIは下書きまで。公開は人が判断。** 自動公開はしません。

### 注意点

- 国土交通省のRSSは省全体が対象です。観光庁だけのフィードは提供されていないため、**キーワードで絞り込む**必要があります。
- e-Stat APIは**無料の利用登録（appId取得）が必要**です。仕様は3.0版を使用します。
- 自治体のオープンデータは形式が統一されていません。**自治体ごとにパーサを個別実装**する前提で見積もります（1自治体あたり半日程度）。

## 3. 絞り込みキーワード

一次候補（いずれかを含めば取り込み対象）：

```
民泊 / 住宅宿泊事業 / 住宅宿泊事業法 / 旅館業 / 旅館業法 / 簡易宿所 /
特区民泊 / 国家戦略特別区域外国人滞在施設経営事業 / 宿泊旅行統計 /
宿泊施設 / 宿泊事業者 / 違法民泊 / 宿泊税
```

除外キーワード（ノイズ対策）：`職員募集` `入札` `人事異動` など。

## 4. 処理の流れ

```
[取得] RSS / HTML / API
   ↓ 重複チェック（URLのハッシュ）
[正規化] タイトル・公開日・発表元・本文URL・PDF URL
   ↓
[絞り込み] キーワード判定 → 対象外は保存だけして非表示
   ↓
[要約] AIで「3行要約」「カテゴリ」「エリアタグ」「事業形態タグ」を生成
   ↓
[下書き登録] CMSへ status=確認待ち で登録
   ↓
[人の確認] 編集者が事実確認・加筆 → 公開
```

## 5. 保存するメタ情報（記事1件あたり）

| 項目 | 例 | 用途 |
| --- | --- | --- |
| `source_id` | `jta-news` | どこから来たか |
| `source_type` | `primary` / `secondary` | 「一次情報あり」ラベルの判定 |
| `origin_url` | 行政発表のURL | 出典リンク |
| `published_at` | 2026-09-05 | 並び順 |
| `fetched_at` | 2026-09-06 03:12 | 取得ログ |
| `verified_at` | 2026-09-06 | **画面に表示する「最終確認日」** |
| `ai_generated` | true / false | 人の確認前かどうか |
| `reviewer` | 担当者名 | 責任の所在 |

## 6. 著作権まわりの実装ルール

- 報道記事は **タイトル・媒体名・公開日・URL のみ**を保存・表示します。本文はデータベースに保存しません。
- 行政資料は、出典表示を条件に引用・再利用が認められる範囲で扱い、**PDFの再配布は行わず元URLへリンク**します。
- 加工した統計データには「○○を加工して作成」と明記します。
- robots.txt を尊重し、禁止されているパスは取得しません。

## 7. 監視

- 取得0件が2日続いたら管理者へ通知（サイト構造変更の検知）。
- 自治体データは `verified_at` から180日を過ぎたものを管理画面で警告表示します。
