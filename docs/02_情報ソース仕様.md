# 情報ソース仕様

収集まわりの設計メモです。実装は `scripts/fetch.mjs` と `scripts/lib/parse.mjs`、設定は `data/sources.json` にあります。

## 1. 基本方針

- **一次情報（行政）が主、報道が従。** 報道は「気づくきっかけ」として使い、根拠は必ず行政の元資料に置きます。
- **取得は1日1回。** 行政サイトに負荷をかけないため、同一プロセスからの連続アクセスは1.5秒以上あけます。
- **本文は保存しない。** 保存するのは見出し・公開日・発表元・リンクだけです。
- **要約を付けるなら、公開前に人が確認する。** 現状は見出しをそのまま並べているため、この工程はありません。

### 注意点

- 国土交通省のRSSは省全体が対象です。観光庁だけのフィードは提供されていないため、キーワードで絞り込みます。
- 上記2つのRSSは **Shift_JIS** です。`scripts/lib/http.mjs` が文字コードを見て変換しています。
- 都道府県別の届出件数は出典がPDFです。`pdftotext -layout`（poppler-utils）で表を文字に起こしてから読み取ります。外部ライブラリを使わない方針の唯一の例外で、入るのは実行環境側だけです（GitHub Actions では `apt-get install poppler-utils`）。
- そのPDFのURLは更新のたびに変わるため、施行状況ページの見出し「都道府県別届出状況一覧」から毎回探し直します。
- 表は「都道府県」「保健所設置市」「特別区」の3列が横に並び、列ごとに通し番号が振り直されます。読み取った各行は名前の末尾（県／市／区）で列を判別し、市は `cityToPref` で都道府県に結び付けて合算します。特別区は東京都に足します。
- 読み取り結果はPDF自身の集計欄と突き合わせ、1件でも合わなければ取り込みません（`checkFilings`）。47都道府県そろわない場合、どの県か分からない市がある場合も同様です。
- 宿泊旅行統計調査も、都道府県別の数字は報道発表の**添付PDFにしかありません**（本文は全国の値だけ）。同じ `pdftotext` で3つの表（延べ宿泊者数・外国人延べ宿泊者数・客室稼働率）を読み取ります（`parseLodgingPdf`）。
- この3表は**第2次速報**で、本文の見出しより1か月前の時点です。サイト上でも時点を明記しています。
- 稼働率の表は半角と全角の符号（`-` と `－`）が混在し、増減が `0.0` と符号なしで書かれる行もあります。両方に対応しています。
- 読み取り結果は表の「全国」の行と突き合わせ、合計が0.5%以上ずれたら取り込みません（`checkLodging`）。
- 厚労省のRSSは省全体（医療・介護・年金など）が対象です。旅館業の話が出るのは多くありません。そのため `exclude` に医療・介護などを足して、tier 1・2 のノイズを抑えています（**tier 3 には除外を適用しない**ので、旅館業・民泊の話は取りこぼしません）。
- 厚労省「旅館業のページ」はニュースではなく資料集です。`data/documents.json` に書き出し、`/docs/` ページで表示します。節の区切りはページ内の `id="h2_freeN"` を目印にしています。
- 通知のタイトルに入っている和暦（例：令和８年４月21日）は西暦に変換しています（`warekiToIso`）。
- 報道は Google ニュースの検索RSSから取っています。**扱うのは見出し・媒体名・公開日・リンクだけ**で、本文は取得も保存もしません。リンク先は Google 経由で各媒体のページに飛びます。
- プレスリリース配信サービス（PR TIMES など）は `outletBlocklist` で除いています。媒体名がドメインでしか返らないものは `outletNames` で読める名前に直しています。
- 地域の判定は、まず都道府県名をそのまま探し、当たった分を本文から取り除いてから市区町村名を照合します。これをしないと「東**京都**新宿区」が京都府と誤判定されます。

## 3. 絞り込みキーワード

`data/keywords.json` の `tiers` で3段階に分けています。

- **tier 3（制度そのもの）**：民泊 / 住宅宿泊事業 / 住宅宿泊管理業 / 住宅宿泊仲介業 / 簡易宿所 / 特区民泊 / 旅館業 / 違法民泊 / 宿泊税 / 外国人滞在施設経営事業
- **tier 2（統計まわり）**：宿泊旅行統計 / 宿泊施設 / 宿泊事業 / 宿泊者 / 客室稼働率 / 延べ宿泊
- **tier 1（周辺情報）**：ホテル / 旅館 / ゲストハウス / 空き家 / インバウンド / 訪日外国人 / 滞在型

除外キーワード（`exclude`）：`入札` `人事異動` `職員募集` `自動車` `河川` など。**tier 3 には除外を適用しません**（制度の話を取りこぼさないため）。

`minpaku-news` のように、そのサイトの内容がすべて対象になる情報源には `forceScore` を指定して、キーワード判定を飛ばします。

## 4. 処理の流れ

```
[取得] RSS / HTML / API
   ↓ 重複チェック（URL＋見出し）
[正規化] タイトル・公開日・発表元・本文URL・PDF URL
   ↓
[絞り込み] tier 判定（forceScore の情報源は素通し）
   ↓
[分類] ルールで「カテゴリ」「エリアタグ」「事業形態タグ」を判定
   ↓
[保存] data/articles.json を更新（見つからなくなったものは削除）
   ↓
[生成] scripts/build.mjs が dist/ に静的HTMLを書き出す
```

※ 現在は見出しをそのまま並べる方式です。要約を付けたい場合は、この流れの「分類」のあとに要約の工程を挟み、**公開前に人が確認する**手順とセットで入れてください。

## 5. 保存するメタ情報（記事1件あたり）

| 項目 | 例 | 用途 |
| --- | --- | --- |
| `source_id` | `jta-news` | どこから来たか |
| `source_type` | `primary` / `secondary` | 「一次情報あり」ラベルの判定 |
| `origin_url` | 行政発表のURL | 出典リンク |
| `published_at` | 2026-09-05 | 並び順 |
| `fetched_at` | 2026-09-06 03:12 | 取得ログ |
| `category` / `areas` / `businessTypes` | 統計・マーケット / 全国 | 絞り込み |
| `score` | 1〜3 | トップページの並べ分け |
| `lastSeenAt` | 2026-09-07 | 消えた記事の判定 |

## 6. 著作権まわりの実装ルール

- 報道記事は **タイトル・媒体名・公開日・URL のみ**を保存・表示します。本文はデータベースに保存しません。
- 行政資料は、出典表示を条件に引用・再利用が認められる範囲で扱い、**PDFの再配布は行わず元URLへリンク**します。
- 加工した統計データには「○○を加工して作成」と明記します。
- robots.txt を尊重し、禁止されているパスは取得しません。

## 7. 壊れたときの気づき方

- すべての情報源で取得に失敗すると `npm run fetch` が異常終了し、GitHub Actions が赤くなります。
- 一部だけ失敗した場合は、実行ログに `✗ <情報源ID>: 理由` と出ます。行政サイトの構成変更が原因のことが多いので、`scripts/lib/parse.mjs` の該当パーサを直してください。
- `data/articles.json` は Git で履歴が残ります。おかしくなったら前の状態に戻せます。
